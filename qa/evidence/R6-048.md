# R6-048 · 显式开启的服务端加速、私有上传进度与断点恢复

## 交付

| 文件 | 内容 |
| --- | --- |
| `src/ui/server-mode.js`（新） | `createUploader`、`createServerReader`、`resumeFrom` |
| `src/r6.html` | `#server-trigger` 按钮 + `#server-panel` 面板（默认 `hidden`） |
| `src/r6-app.js` | `bindServerMode()`：状态机、进度、打开服务端视图 |
| `src/r6.css` | 面板与进度条样式（沿用 R6-003 令牌） |

### 关键设计

- **默认关闭，显式开启。** 折叠面板里先勾「我了解会上传到服务器」（`#server-optin`），
  勾选前文件选择框与「开始上传」都是 `disabled`。不勾就不会有一个字节离开本机。
- **状态是可见的**：`未开始 → 准备中… → 上传中 N%（已传/总片）→ 校验并封存… →
  服务端索引中… → 已就绪，可打开服务端视图`；暂停显示「已暂停（分片已保留）」，
  失败显示「失败：<原因>」。
- **进度单调**：`percent` 钳制在 0–100，末片短也不会让进度条倒退。
- **断点恢复来自服务端回答**：`resumeFrom(status)` 优先用 `status.resume`，
  退化时按 `parts[].part_no` 补集计算；上传器从不猜测服务端已有哪些片。
- **暂停 = 停止后续分片并保留会话**，「继续」用同一 session id 只补缺片。
- **服务端视图是读视图**：`openServerView` 用 `provider.open(fileId)` 分页取行，
  从不下载整文件；详情走 `reader.detail(ordinal)`。

## 验收

```
node --test tests/r6/server-mode.test.cjs
```

8 项全绿：

- `a full upload reports monotonic progress and seals once` —— 进度不倒退、只封存一次。
- `resume uploads only the missing parts`、`resumeFrom falls back to the parts list when the server does not say`
- `cancelling stops before the next part and keeps the session`
- `a transport failure surfaces as a failed state with a code` —— 失败有 code，不是静默。
- `index polling reports phases and settles on ready`、`a failed index job is reported, not silently left pending`
- `the server reader pages without downloading the file`

## 已知限制

- 面板只有一个文件槽位，不做批量队列（本机导入仍是主路径，服务端加速是可选旁路）。
- 暂停状态下刷新页面会丢失 session id（会话仍在服务端，但页面不再持有它）；
  恢复需要重新选文件后由 `resumeFrom` 重建，尚未把 session id 写进 `localStorage`。
- 页面 CSP 为 `script-src 'self'`：任何 QA 探针的 `wait_for_function` 谓词必须是函数表达式，
  裸表达式会被页面内的 `eval` 拒绝（门禁已按此写法修正）。
