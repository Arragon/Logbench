# R6-045 · ServerProvider：用分页读取替换整文件下载解析

## 交付

`src/providers/server.js`（新），在 `server/frontend.py` 的 R6 bundle 里与本地 provider 并列。

`CAPABILITIES(kind='server', write=true, max_page_records=2000, max_page_bytes=4194304)`。

| 方法 | 行为 |
| --- | --- |
| `open(fileId)` | 读索引状态，暴露 `coverage`/`generation` |
| `headers/getRecords/getTimeline/seek` | 全部走 opaque id，分页读取 |
| `detail(ordinal)` / `readRaw(recordId)` | 详情与原文区间，不下载整文件 |
| `ensureIndex` | 只按 file id 请求，从不发送路径 |
| `search/poll/cancel/resume/queryPage` | 绑定到创建它的快照 |
| `exportQuery` | 流式导出入口（服务端见 R6-049） |

### 关键设计

- **能力声明与契约一致**：`max_page_records=2000`、`max_page_bytes=4 MiB`；
  超限的页请求在**发送前**就被拒绝，不靠服务端 400 兜底。
- **写请求带 `X-LogBench-CSRF`，读请求不带**：跨站点页面不能借浏览器身份写数据。
- **record id 只做 URL 编码的最小必要处理**：`<file_id>:<ordinal>` 的冒号必须保留
  （`encodeURIComponent` 会把它变成 `%3A`，服务端就找不到记录）——由 `encodeRecordId()` 统一处理。
- **失败先于状态**：`close()` 之后所有调用直接以 `closed` 失败，不会「关掉了还发请求」。
- **过期应答丢弃**：`open()` 之后再到的旧应答被丢弃（`dataset_replaced`）；
  旧查询的结果不能覆盖新查询（`stale_query`）。

## 验收

```
node --test tests/r6/server-provider.test.cjs
```

12 项全绿：

- `capabilities say server, and page limits match the contract`
- `a page request over 2000 rows is rejected before it is sent`
- `writes carry the csrf header and reads do not`
- `a reply that arrives after open() is discarded` / `an older query cannot publish its result`
- `poll/resume/cancel address the snapshot they were created with` / `the provider refuses unknown query ids instead of guessing`
- `ensureIndex asks the server by file id and never sends a path`
- `detail and raw reads use the opaque record id`
- `close makes every later call fail as closed`
- `a server error becomes an error with the server code`

浏览器端的真实闭环见 `qa/evidence/M4-gate.md` 的 `ui` 用例：服务端视图渲染 200 行、
`#file-label` 为 `服务端 · f_…`、页面错误 0——整文件从未下载到本地。

## 已知限制

- 只有「服务端已建索引」的文件可读；未索引时 `ensureIndex` 入队并返回 `pending`，
  视图层显示「索引中」而不是空结果。
- 页大小上限是硬上限，前端没有做「按字节动态缩小页」的自适应（2000 行/4 MiB 已覆盖
  当前单行最大规模；更宽的记录靠详情接口分段取）。
- 与本地 provider 共享视图层，但两者的 `coverage`/`relation` 来源不同：
  服务端以快照为准，本地以内存索引为准，视图层只读不推断。
