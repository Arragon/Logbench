# M2 Gate 证据：本机 5×20 MiB / 10×100 MiB 导入搜索纵切

> Gate 票：`R6-031`　｜　核验范围：`R6-019`–`R6-030`　｜　日期：2026-11-03
> 结论：**5×20 MiB 纵切全部达标；`R6-024` 查询路径未接线、两个能力缺口已登记，Gate 不关闭。**

## 1. 逐项判定

| # | 必须证据 | 判定 | 依据 |
|---|---|---|---|
| 1 | 5×20 MiB 与 10×100 MiB；选择反馈 ≤100 ms、进度 250–500 ms、首批 ≤3 s | **5×20 PASS / 10×100 见 §4** | 面板首绘 **0.8 ms**、首个可读批次 **2.36 s**；见 `local-vertical.json` |

## 2. 本次执行数字（`local-vertical.json`）

| 指标 | 目标 | 实测 |
|---|---|---|
| 选择反馈 | ≤100 ms | **0.7 ms**（同步登记 + 首帧绘制） |
| 首个可读批次 | ≤3000 ms | **2380.9 ms** |
| 5×20 MiB 整批 | — | **7.05 s**，5 文件 651,658 条 |
| 搜索 p95（30 次，含重复命中缓存） | p95 ≤1800 ms | **425.7 ms** |
| 40,000 跳转 DOM（50k 逻辑窗口） | <300 | **98** |
| 抽屉打开位移 | 0 | **Δx/Δw/Δh = 0** |
| 锚点位移 | ≤2 px | **0 px**（按记录 ordinal 比对 boundingRect） |
| "0 条"是否在未扫完时出现 | 0 次 | **0 次** |
| 刷新后索引复用 | 5 文件 / 0 任务 | **5 / 0** |
| 10×100 MiB 整批 | — | **54.46 s**，10 文件，累计 7,117,192 条，0 失败 |

冷/热必须分开看：同一查询重复 3–4 次，第二次起命中结果缓存（p50 0.2 ms）。**冷查询**的首次数值是 300–880 ms（`M2-gate-big` 的 per-label max：884/313/308/341/305/334/309/336/309 ms）。把缓存命中算进 p50 会得出"查询只要 0.2 ms"的假结论，因此上表只把 p95 当作预算结论。

环境：Chrome 156（`channel='chrome'`，headless）、`http://192.168.1.3:<port>`（`isSecureContext=false`）、12 逻辑核。页面零 JS 异常。

## 3. 未达标与缺口（不关闭 Gate 的理由）

1. **B-016 危险正则未接入查询路径**：隔离器本身已在真实 Worker 上验证（802 ms 终止、主线程 22 ms 心跳），但页面上的 regex 查询仍由 30 s 预算保护，没有 2 s 单片终止。第 3 项因此只能判"部分"。
2. **B-017 页面为并行视图**：新栈在 `/r6`，R5 仍服务 `/`。`app.js` 的三层覆盖链未改造，因此"列/详情/时间线全部回归"是对新视图的回归，不是对 R5 页面的替换验证。
3. **B-018 结果只取第一页 200 条**：`next_cursor` 已返回，页面无"加载更多"。
4. **B-020 滚动整窗重建**：98 行下无问题，1 GiB/640 万条的极端情况未做行复用。

## 4. 10×100 MiB 阶段（`M2-gate-big/local-vertical.json`）

| 指标 | 实测 |
|---|---|
| 10×100 MiB 导入 | **54.46 s**（10 文件，2 并发） |
| 索引结果 | 15/15 文件 `indexed`（含前一批 5 个），**0 失败** |
| 累计记录 | **7,117,192** 条（≈1 GiB 原文） |
| 搜索 p95 | **340.9 ms**（30 次，含重复查询命中缓存；冷查询 300–880 ms） |
| 跳转后 DOM | **98** 行 |
| 刷新后 | 15 文件仍在，任务数 0，主题恢复为 `nord` |

冷/热分离：每类查询重复 3–4 次，后续命中结果缓存（p50 0.1 ms），首次冷查询 300–880 ms。两者分别记录，不把缓存命中当作性能提升。

**这一阶段的第一次运行失败**：脚本把 10×100 MiB 一次性读成 ArrayBuffer，页面被 1 GiB JS 堆压垮（`TargetClosedError`）。改为走真实文件选择器（Chrome 用磁盘支撑的 Blob）后通过。这是**测试脚本**的缺陷，不是流水线的：真实用户本来就不会把整批文件读进 JS 堆。
