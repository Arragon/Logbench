# R6-049 · 按查询快照的流式导出与权限校验

## 交付

`GET /api/v2/queries/{id}/export?format=ndjson|csv&max=N`（`server/query/api.py::export`）。

| 参数 | 语义 |
| --- | --- |
| `format` | `ndjson`（默认）/ `csv`，其他值 400 `INVALID_FORMAT` |
| `max` | 1 … `EXPORT_HARD_CAP`(100,000)，默认 `EXPORT_MAX_RECORDS`(10,000) |

响应头：`Content-Type`（按格式）、`Content-Disposition: attachment; filename="<query_id>.<fmt>"`、
`X-LogBench-Export-Rows`、`X-LogBench-Export-Truncated`、`X-LogBench-Export-Total`。

### 关键设计

- **导出的是快照，不是「当前结果」**：序号来自 `query_hits`（按 `seq` 排序、`LIMIT max`），
  与分页看到的是同一批命中；重新执行查询不会改变已导出的行。
- **先授权再读盘**：`snapshots.get(query_id, principal)` + `_authorize(actor, file_id)`
  在打开分片之前完成；他人查询、撤销后的文件一律 404，而不是「先查了再说」。
- **按 500 条一批从分片取记录**，写进 `SpooledTemporaryFile`（4 MiB 后自动落盘），
  再以文件流返回：调用方不必把整份导出读进内存。
- **截断是显式的**：`max` 用尽或字节数超过 `EXPORT_MAX_BYTES`(64 MiB) 都会把
  `X-LogBench-Export-Truncated` 置为 `true`，并始终给出 `X-LogBench-Export-Total`
  （快照命中总数），让调用方知道「还有多少」。
- **单条记录走统一的 RecordHeader 投影**：导出字段与详情接口一致，不另立一套 schema。

```

```

## 已知限制

- 先落 `SpooledTemporaryFile` 再发送，不是真正的「边查边发」：好处是长度可知（可带
  `Content-Length`）、失败时不会已经吐了半个文件；代价是多一份临时磁盘占用（上限 64 MiB）。
- 不支持断点续导（没有 Range 语义）；超过 100,000 行应改用查询接口分页消费。
- CSV 只做最小转义（引号、逗号、换行），不带 BOM；需要 Excel 直开的场景由前端另加。
