# R6-072 · 持久采集调度、增量追踪、退避与断线补采

> Linear：`INH-2315` · 里程碑 M7 · 状态：**已实现，退避与配额实测**

## 变更
- `server/collectors/scheduler.py`：`Quota`（全局 4 / 每 host 2，记录峰值）、`backoff`（指数+抖动+上限）、
  `CollectScheduler.run_source/_run_mapping/_sync_file/_record_error/_finish_job/due_sources/tick/start/stop`。
- 观察窗口顺序读取，内部按 `readWindow` 提交，**不每 4 MiB 重新握手**；
  `bytes`（已提交）与 `readBytes`（含头部采样）分开统计，避免把读放大当吞吐。
- 错误分级：`retry`（timeout/transport_error/locked/busy…）写 `retry_at`；
  `manual`（auth_failed/hostkey_changed/permission_denied…）停到人工；
  `file` 只影响该文件。恢复成功后清除 `retry_at`。
- 每轮发布引用型事件：`archive_commit`、`rotation`、`gap`、`record_revision`、`index_commit`、
  `task_progress`、`source_error`（不带正文）。
- 新增 `_mark_missing`：文件在两次扫描之间消失即置 `disappeared`，原文保留。

## 运行接线
`Application.start_background()` / `stop_background()` / `background_state()`：构造调度器
（注入 `IncrementalIndexer`）并启动 `lb-collector` 线程与 `lb-watchdog`（60 s 一次
`Lifecycle.enforce()`）。`httpd.main()` 只在 `LOGBENCH_COLLECT=1` 时启动，tick 默认 5 s
（`LOGBENCH_COLLECT_TICK` 覆盖），停止时 join 并收尾。冒烟：`running=False → True → False`，
`lastTick` 有 `quota` 快照。默认关闭的理由见 B-041。

## 已知边界
- 目录发现 60 s / 活动检查 2 s 为默认值，可配；它们是**轮询周期**，不是端到端延迟承诺。
- 无真实远端端点（B-007），本轮所有协议行为在 M6 门禁里 BLOCKED，调度器以本机目录适配器与夹具验证。
