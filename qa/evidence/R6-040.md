# R6-040 · 授权记录/原文/时间线/索引状态 API

## 交付

`server/indexing/read_api.py`，从 `Application.route` 接入：

| 路由 | 说明 |
| --- | --- |
| `GET /api/v2/files/{id}` | 索引状态：三层状态、记录数、coverage `pending/partial/complete`、count relation |
| `GET /api/v2/files/{id}/timeline?page=&pageSize=` | 20/50/100/150 分页，返回覆盖与 count relation |
| `GET /api/v2/files/{id}/generations` | 代次与状态历史 |
| `GET /api/v2/files/{id}/seek?line=|byte=` | 按物理行或字节定位记录，两者互斥 |
| `GET /api/v2/records/{recordId}` | 详情：结构字段 + 规则证据 + 版本身份，body 有上限并带游标 |
| `GET /api/v2/records/{recordId}/raw?start=&end=&max=` | 原文字节区间，返回精确边界与续读游标 |

### 安全与正确性要点

- **线上不出现路径。** 请求只带 opaque `file_id`/`record_id`；文件位置来自该
  principal 的 `raw` 层（含授权相对路径），再经 `Application.open_file`
  （`O_NOFOLLOW` + 目录 fd）打开。
- **先授权，且失败不可区分。** 所有路由先解析 `raw` 层；他人文件、不存在文件、
  已撤销授权返回同一个 `not_found`（错误体形状一致），不暴露存在与否。
- **缺索引是 `pending` 而不是空结果。** 状态接口对未建索引的文件返回 200 +
  `coverage.state=pending`、`count.relation=unknown`；时间线在规则层缺失时同样
  返回 `pending`，避免「没有错误」的误导。
- **截断不等于完整。** 详情 body 上限 64 KiB，超出给 `truncated` + `next`；
  原文读取上限 256 KiB，`complete` 为 false 时给精确 `next` 字节偏移。
- **不返回另一个版本的记录。** 详情可带 `?version=`，只读该版本；版本不存在即
  404，不会悄悄换成当前版本。
- **UTF-8 边界。** 从字符中间开始读会把起点推进到下一个字符边界并回报
  `adjusted_start`；结束在字符中间则丢弃残段并让游标停在完整边界上。

## 验收命令

```
env -u PYTHONPATH ~/.local/bin/python3.9 -m unittest tests.test_r6_record_api -v
```

16 项全绿（含真实 HTTP + 真实磁盘）：

- 原文区间与磁盘字节逐字相等（三组随机区间），续读分片拼接后等于完整区间
- 三字节汉字中间起读/结束读的边界与 `next` 正确，文本中无 `U+FFFD`
- 篡改 record id、跨代次、他人身份、撤销后读取全部 404 且错误体一致
- 时间线 20/50/100/150 分页 + `has_prev/has_next`；`pageSize=33` 拒绝
- 巨型 Traceback（6000+ 帧）：body 截断带游标，原文可分段取完
- GET 不要求 CSRF，但 Host 校验仍生效（421）
