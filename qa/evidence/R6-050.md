# R6-050 · 私有上传、索引、查询与下载的端到端隔离

## 交付

隔离不是一处开关，而是四个位置同时成立，且失败形状一致：

| 位置 | 机制 | 测试 |
| --- | --- | --- |
| 上传会话 | 会话行带 `principal`，`get/put_part/commit/cancel` 全部按 principal 过滤 | `test_r6_uploads`、`test_r6_private_isolation` |
| 文件可见性 | 读路径先解析该 principal 的 `raw` 层，再经 `open_file` 打开 | `test_r6_record_api` |
| 查询 | `POST /queries` 对外人文件返回与「不存在」相同的错误体 | `test_r6_query_api` |
| 导出 | 先 `snapshots.get(principal)` + `_authorize`，再读分片 | `test_r6_query_api` |

### 关键设计

- **错误体不可区分。** 他人文件、不存在的文件、已撤销授权统一返回
  `404 not_found`（或查询域的 `404 unknown_query`），不泄露「存在但你没权限」。
- **撤销立即生效且穿透到底**：`/api/v2/files/{id}`、`/records`、`/records/{id}`、
  `/queries/{id}`、`/queries/{id}/export` 五条路径同时关闭；已封存的上传会话视图
  也会复读 `raw` 层后失效（`unknown_session`）。
- **同一份字节可以由两个 principal 各自索引**：身份不是内容哈希，而是
  「谁的文件行 + 谁的版本指针」，因此互不可见且互不干扰。
- **路径从不出现线上**：请求只带 opaque `file_id`/`record_id`，真实路径只存在于
  服务端 `raw` 层的授权记录里。

## 验收

```
env -u PYTHONPATH ~/.local/bin/python3.9 -m unittest tests.test_r6_private_isolation -v
```

7 项全绿：

- `test_the_owner_can_read_everything_they_created` —— 正例先立住，避免「全 403 也算隔离」。
- `test_the_same_ids_are_absent_for_another_principal` —— 同一批 id 对他人全部不可见。
- `test_another_principal_cannot_upload_into_the_session` —— 不能往别人会话里写片。
- `test_another_principal_cannot_cancel_or_seal_the_session` —— 不能替别人取消/封存。
- `test_query_creation_for_a_foreign_file_does_not_leak_existence` —— 建查询也不泄露存在性。
- `test_revoking_the_owner_closes_every_path` —— 撤销穿透所有读路径。
- `test_two_principals_can_index_the_same_bytes_independently` —— 同字节、两身份、互不可见。

真实 HTTP（`qa/evidence/M4-gate.md` 的 `isolation` 用例）：以另一对端 `10.9.9.9`
访问 5 条路由，5/5 返回 404，错误码分别为 `NOT_FOUND`（文件/记录）与
`unknown_query`（查询/导出）。

```
GET /api/v2/files/<file_id>              404 NOT_FOUND
GET /api/v2/files/<file_id>/records      404 NOT_FOUND
GET /api/v2/records/<file_id>:0          404 NOT_FOUND
GET /api/v2/queries/<query_id>           404 unknown_query
GET /api/v2/queries/<query_id>/export    404 unknown_query
```

## 已知限制

- 门禁里第二个 principal 通过 `Application.handle(peer=...)` 注入对端地址，而不是真的
  从第二个源地址发起 TCP 连接：同一进程无法可移植地绑定第二个回环地址。HTTP 层其余
  用例都是真实 socket；身份推导本身由 `test_r6_private_isolation` 覆盖。
- 身份即 IP（v3.0.3 的既有模型），没有强认证：同一 NAT 后的两个用户不是隔离的两个 principal。
  这是产品约束，不是本票的缺陷，但必须写在证据里。
- 「越权读计数被拒」由查询接口 404 覆盖；没有单独的「计数接口」可越权（计数只随快照返回）。
