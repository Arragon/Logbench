# R6-043 · 服务端候选规划与精确语义回退

## 交付

`server/query/planner.py` —— 只做一件事：给出**候选超集**，并在无法证明时诚实地退回全扫描。

`Plan` 携带：`mode`（`postings` / `btree` / `scan`）、`superset`、`reason`、`predicates`、
`gram_terms`、`explain`、`postings_version`、`postings_complete`、`sql`、`params`、
`projection`、`joiner`。

### 关键设计

- **两种失败模式优先于速度**：漏掉一条匹配（错误答案）和伪造快路径（把表扫描说成走索引）。
  因此每个剪枝动作都必须由数据本身的性质支撑，`explain` 里放的是真实的
  `EXPLAIN QUERY PLAN` 输出。
- **拒绝剪枝的情形**：正则（`regex`）、整词（`whole_word`）、短语 gram 长度不足（`< 3`）。
  两个汉字的中文查询会**回退**（false negative 风险高于收益），不会靠 bigram 硬剪。
- **倒排覆盖不全就不能剪**：`postings_complete=false` 时只能取候选，不能声称「其余不匹配」。
- **投影版本要对齐 matcher**：haystack 按 `v1`（`message`、`body`）与 `v2`（再加
  `fields`/`logger`/`fn`/`src`）拼接，倒排按 `field`=`grams/vN` 过滤，避免
  「索引里没有、matcher 里有」的漏检。
- **连接子是 `and` 取交集、`or` 取并集**，SQL 与内存路径共用同一 `joiner`。
- **FTS 能力是探测出来的**：`fts_available()` 真跑一次虚表探测，不按「应该有」假设。
- **LIKE 元字符转义**：`%`/`_` 在字面量里被转义，避免 `a_b` 命中 `axb`。

## 验收

```
env -u PYTHONPATH ~/.local/bin/python3.9 -m unittest tests.test_r6_query_planner -v
```

13 项全绿，核心是**与全量扫描 oracle 的差分**：

- `test_every_case_matches_the_full_scan_oracle` —— 13 组查询 × 全量扫描结果逐条比对，
  规划器给的是超集，最终结果必须与 oracle 完全一致。
- `test_a_literal_uses_postings_and_returns_fewer_candidates_than_records` —— 真的剪掉了候选，
  不是「说是 postings 其实全扫」。
- `test_two_character_chinese_falls_back_instead_of_pruning`、`test_a_regex_never_prunes`、
  `test_whole_word_never_prunes` —— 三种必须放弃剪枝的情形。
- `test_explain_shows_the_index_or_admits_a_scan` —— `explain` 区分「索引命中」与「带 WHERE 的扫描」。
- `test_postings_without_coverage_cannot_prune`、`test_fts_availability_is_probed_not_assumed`
  —— 覆盖不全与能力探测。
- `test_v2_finds_text_in_fields_that_v1_does_not_index`、`test_a_phrase_spanning_message_and_body_is_still_found`
  —— 投影版本与跨字段短语。
- `test_like_metacharacters_are_literal`、`test_level_and_time_predicates_reach_sql`、
  `test_scan_order_is_ordinal_and_resumes_after_the_cursor`。

## 已知限制

- 倒排只服务「连续字面量」，词干/同义词/模糊匹配一概走全扫描。
- 规划结果不带代价估计，只给 `mode` 与 `explain`：本机数据规模下选择基本退化为
  「能剪就剪、不能剪就扫」，代价模型暂无收益空间（可在 M9 性能基准里再评估）。
- `btree` 路径依赖 `ts_key`/`level` 的实际选择率，选择率差时 SQLite 可能仍选扫描；
  `explain` 会如实反映，不做包装。
