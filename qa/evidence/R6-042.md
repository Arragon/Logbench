# R6-042 · 异步查询 API、固定快照与授权游标

## 交付

| 文件 | 作用 |
| --- | --- |
| `server/query/api.py` | 路由与请求校验，接入 `Application.route` 的 `/api/v2/queries` |
| `server/query/snapshots.py` | 快照存储、HMAC 签名游标、分页与续查 |

| 路由 | 语义 |
| --- | --- |
| `POST /api/v2/queries` | 校验 spec、冻结快照、交给后台池，返回 `item` + `accepted` |
| `GET /api/v2/queries/{id}` | `QueryState` 超集：`state`/`count`/`coverage`/`plan`/`signature`/`order_final` |
| `GET /api/v2/queries/{id}/records?limit=&cursor=` | 按快照内 `seq` 分页，游标签名 |
| `POST /api/v2/queries/{id}/continue` | 预算停下的查询凭 resume token 续扫 |
| `DELETE /api/v2/queries/{id}` | 取消：保留已得结果，但计数关系降为 `unknown` |

### 关键设计

- **请求线程不扫描。** `create()` 只做校验 + 冻结快照 + 交给有界池；扫描在后台，
  轮询走 `GET`，避免一个大文件查询占住一个连接。
- **快照冻结「答案是关于什么」**：file、generation、index version、rule version、
  query signature。代次一变，旧游标立刻失效（`cursor_expired`），而不是悄悄换成新代次的数据。
- **游标不是 offset**：`q/o/p/a/v/sig/t` 六段签名，覆盖查询、位置、身份、ACL 版本、
  快照版本、时间戳。篡改 → `400 invalid_cursor`；跨身份复用或权限变更 → `410 cursor_expired`；
  查询不存在/不属于当前身份 → `404 unknown_query`。
- **计数关系由覆盖派生，不由「看起来跑完了」推断**：`done ⇒ exact`、
  `paused ⇒ at_least`、`cancelled ⇒ unknown`（C3/C5 不变量）。
- **撤销权限立即生效**：`acl_version` 参与签名，撤销后游标即失效，不会继续吐旧结果。

## 验收

```
env -u PYTHONPATH ~/.local/bin/python3.9 -m unittest tests.test_r6_query_api -v
```

15 项全绿。关键几条：

- `test_create_returns_before_the_scan_when_the_worker_pool_is_enabled` —— 池开启时
  `POST` 早于扫描返回，扫描不在请求线程内完成。
- `test_a_finished_query_is_exact_with_complete_coverage` / `test_a_budget_stop_is_at_least_with_a_resume_token`
  —— `exact` 与 `at_least` 的区分，以及暂停必须带续查凭据。
- `test_paging_walks_the_snapshot_with_signed_cursors`、`test_a_tampered_cursor_is_refused`、
  `test_a_cursor_from_another_identity_is_refused` —— 分页正确性与三种游标拒绝。
- `test_revocation_stops_reads_immediately`、`test_a_new_generation_invalidates_old_cursors`
  —— 授权与代次变更的即时性。
- `test_unknown_and_foreign_files_are_indistinguishable` —— 他人文件与不存在的文件返回同一错误体。

真实 HTTP 的端到端复现见 `qa/evidence/M4-gate.md` 的 `query` 用例（宽查询 48,470 命中、
`relation=exact`、覆盖 6,291,739/6,291,739 B）。

## 已知限制

- 创建返回 200 + `accepted: true`，而不是 202：前端 `fetch` 封装只在 2xx 上解析 JSON，
  改动状态码会把「已受理」变成一条错误路径。语义由 `accepted` 承载，见 `QueryState` 超集说明。
- 结果集本身不落盘，落盘的只有命中序号（`query_hits`）；导出另行处理（R6-049）。
- 分页上限 2000 在服务端强制；**4 MiB 页字节上限只在 `ServerProvider` 侧强制**
  （发送前拒绝），服务端不按字节截断一页——2000 条超大记录的详情仍会走单条接口补取。
- 并发查询数由池大小决定，超出排队；排队中的查询 `state=queued`，不计入 `scanned_bytes`。
