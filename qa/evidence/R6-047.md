# R6-047 · 流式分片上传、落盘确认、幂等续传与封存

## 交付

`server/uploads/api.py`（路由）+ `server/app.py`（二进制请求体路径）。

| 路由 | 说明 |
| --- | --- |
| `POST /api/v2/uploads` | 建会话：name、size、chunkSize |
| `GET /api/v2/uploads/{id}` | 进度、缺片清单、封存后的 `job`/`indexed` |
| `PUT /api/v2/uploads/{id}/parts/{n}` | 单片，body 为**原始字节** |
| `POST /api/v2/uploads/{id}/commit` | 校验、拼装、封存、入队索引 |
| `DELETE /api/v2/uploads/{id}` | 取消（保留分片） |

### 关键设计

- **唯一的非 JSON 写路径**：`app.py` 用 `is_upload_part_path()` 让分片请求跳过 JSON 解析与
  `application/json` 校验，原始字节放在 `request_local.body`；`MAX_UPLOAD_PART = 8 MiB`
  单独设传输上限（`transport_limit()`），不影响 JSON 接口的 1 MiB 限制。
- **CSRF 仍然必需**：这是浏览器发起的写操作，跨站页面不能替用户把磁盘填满。
- **摘要不匹配在写盘前拒绝**（`digest_mismatch`）；非末片长度必须等于 `chunk_size`
  （`part_size_mismatch`），否则拼装会静默错位。
- **封存幂等到任务级**：重试封存不新建索引任务（本轮修复，见 R6-046）。
- **封存后复核授权**：会话视图在 `file_id` 存在时复读 `raw` 层，文件被撤销后
  会话视图同样 404（`unknown_session`），不会留下一扇「还能看到已撤销上传」的窗。

## 已知限制

- 一次上传一个文件，不支持多文件并发会话（前端队列在上层，不在会话层）；
  并发会话数由 B-029 之外的会话上限约束（默认 global 4 / per principal 2，见 R6-046）。
- 分片大小上限 4 MiB（服务端 `MAX_PART_BYTES`），下限 64 KiB；不支持的中间值在创建时拒绝。
- 封存时整文件拼接会短暂占用一份源大小的临时空间，未做「边拼边校验边删除」的流式改写；
  1 GiB 级别上传的磁盘峰值因此约为 2× 文件大小（GC 前）。
- **分片寻址用片号而不是客户端 offset**（B-031）：片边界由服务端 `chunk_size` 决定，
  拼装不会错位、同片重传天然幂等；代价是没有「从任意 offset 续传」的自由度。
- 上传路径未在 1 GiB / 10×100 MiB 规模实测内存（B-031）：结构上峰值只与单片大小相关，
  但缺实测曲线。
