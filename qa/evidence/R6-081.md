# R6-081 · 规则影响预览、分层重算与历史命中证据

## 交付

| 文件 | 职责 |
| --- | --- |
| `server/rules/api.py` | `GET /api/v2/rules`（可选真实签名）、`POST /api/v2/rules/impact`、`POST /api/v2/rules/trial`、`POST /api/v2/rules/{id}/apply` |
| `src/ui/rule-impact.js` | 规则编辑（提取/异常/节点）、影响面板（按层计数与文件表）、试跑（证据卡）、保存并应用 |
| `server/indexing/service.py` | 修复：规则重算时按**已发布结构版本的 shard 路径**读取，而不是用新规则语义重新拼出的 tag 路径 |
| `tests/test_r6_rule_impact.py` | 15 项：签名、0 影响基线、样式改动、分层影响、试跑、409、应用后结构层不变 |
| `qa/r6/rule_impact.py` | 真实 API + 真实页面，26 项 |

### 关键语义

- **影响是签名预测，不是"记录会变多少"。** 接口返回 `affected_files`，并在 `notes` 里写明不代表命中记录数变化。
- **样式不是语义。** 只改颜色/形状/名称/优先级 → 0 个文件受影响（实测基线 `affected=0`，改样式后仍 `0`）。
- **分层影响准确：** 改异常 → 规则层 2、检索层 2、结构层 0。改提取器 → extract 签名变化、规则层受影响。
- **应用不重分帧。** `apply` 保存（带 `expectedRevision` 乐观并发）并排队重建；实测应用前后**结构层签名完全相同**（`sig1-20c4fa…`），重建只动派生层。
- **旧证据不被草稿改写。** 新版本发布前旧指针继续可读（R6-038 的发布语义），`apply` 只新增版本。
- **试跑用同一个引擎。** 样本经服务端 Node 池真实分帧 + 规则执行，返回字段/异常/节点与证据行；样本文本 ≤256 KiB，服务端无法读取本机文件，因此"试跑本机日志"不可能悄悄上传统计。
- **规则列表默认不启动 Node 池。** 签名是显式请求（`?signatures=1`）；打开规则页不应在服务端凭空拉起一个解析进程。

## 验收命令

```
env -u PYTHONPATH ~/.local/bin/python3.9 -m unittest tests.test_r6_rule_impact     # 15 项
env -u PYTHONPATH ~/.local/bin/python3.9 qa/r6/rule_impact.py --out qa/evidence/M8-rule_impact
```

实测（`qa/evidence/M8-rule_impact/rule_impact.json`）：

| 场景 | 可见 | 受影响 | 规则层 | 检索层 | 结构层 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 当前生效规则 | 2 | 0 | 0 | 0 | 0 |
| 只改颜色/形状/名称 | 2 | 0 | 0 | 0 | 0 |
| 新增一条异常条件 | 2 | 2 | 2 | 2 | 0 |
| 应用并重建之后 | 2 | 0 | 0 | 0 | 0 |

- 试跑：`framed_records=10`，首条记录带提取字段与命中证据。
- 并发：错误修订号 → 409 `revision_conflict`；应用后修订号 +1，排队 2 个重建任务。
- 结构层签名应用前后相同（未重新分帧）。
- 界面：未预览时"保存并应用"禁用，预览后启用；预览面板数值与 API 一致（受影响 0）。

## 已知限制

- 编辑器覆盖提取/异常/节点（含 AND/OR、优先级、10 形状、12 色与手动颜色），但没有 R5 的撤销栈、快捷键与批量导入。见 B-045。
- 影响扫描上限 5000 个文件，超出时 `truncated=true`；文件表只列前 200 个。
- 试跑样本 256 KiB 上限；超大记录（>4 MiB 单批）需要在真实文件上验证。
- 未实现"个人草稿与生效版本分离"的持久化：草稿只在当前页面存活，刷新即丢失（票面要求"不同规则草稿不互相提交"，此点满足；跨会话草稿见 B-046）。
