### 关键语义

- **本机原文不会因为"混合"而离开页面。** scope 拆成 local / server 两段，各自跑各自的查询；只有时间戳、等级、序号参与归并。`qa/r6/mixed_scope.py` 直接检查浏览器请求日志：任何请求的 URL 与 body 都不含本机文件名或样本标记。
- **排序是三段稳定：** 时间 → 来源（本机先）→ 文件序 → 序号。同一时间戳的多条记录全部保留，不做去重。
- **无时间戳不被猜位置。** `time` 模式下无时间戳文件被排除并记入 `excluded`（原因 `no_time_domain`）；`search` 模式下排在有时间记录之后，且 `order_final=false`。
- **计数不作假。** 任一子查询未完成 → `at_least`；任一失败 → `at_least` 且 `coverage.failed` 指名文件与错误码；全部失败 → `unknown`。永远不会出现"部分扫描 + exact 0"。
- **服务端查询是异步的。** 首个回包常常是 `queued`。`wait({timeout_ms})` 是有界等待；把首个空回包渲染成"0 条"正是本模块要避免的错误。
- **两种传输取行方式不同且被显式处理：** 本机返回命中序号（再取 headers），服务端 query state 只有计数、行来自 records 分页。

## 已知限制

- 一次 scope 查询每个文件只取一页（上限 400 条/文件）；超出窗口需要缩小时间范围，阅读区没有"继续加载"。见 B-042。
- 混合归并在浏览器内完成，规模取决于窗口内命中数，不是全库归并；本票不承诺跨全库时间序。
- 服务端子查询的失败重试只体现在 `coverage.failed` 与 `at_least`，没有自动重试按钮。
- 目标机（Linux 双路 E5）未复跑，全部数字来自本机 macOS。见 B-050。
