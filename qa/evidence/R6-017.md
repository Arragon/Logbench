## 往返路径（不是内存内自证）

浏览器内构建清单并封卷 → Python 把 4 个卷写成**真实文件** → 另起一个 HTTP 服务提供这些文件（带 CORS）→ 页面 `fetch` 回来 → 逐卷校验 → 恢复进 staging 代次 → 切换指针 → 重新算摘要比对清单。

## 实测要点

- 卷上限 64 MiB：4 卷 `64/64/64/40` 字节，总量与文件声明一致。
- 少卷、多卷、乱序一律拒绝（`missing_volumes` / `unknown_volumes` / `volume_order`）。
- 篡改 1 个字节 → `volume_digest_mismatch`，且**未发布任何内容**（`readPublished` 仍为 null）。
- 恢复后两个文件的摘要与清单一致，中文正文可读。
- 清单不含 `text`/凭据/完整搜索词（单测断言 `JSON.stringify(manifest)` 不含这些键）。
- 未封卷（卷无摘要）的清单被拒，避免恢复出"看起来完整"的半成品。

## 边界

- 摘要用 64 位 FNV-1a：私网 HTTP 下 `crypto.subtle` 不可用，这是可用性与强度的现实取舍。它检测传输损坏与误替换，**不是签名**，不防主动伪造。
- 浏览器多文件下载权限未做交互验证；当前由 Python 代写文件，等价于用户把卷保存到磁盘。OPFS 流式写入未实现（可选增强）。
