## 被断言的不变量

- `add()` 同步登记任务（页面实测首次绘制 **0.8 ms**），随后在宏任务里启动，不阻塞首帧。
- 每次 `slice` 不超过 `chunkSize`（默认 2 MiB）；测试断言所有读取长度 ≤ 上限且总字节等于文件大小。
- 同时在飞的写请求 ≤ `maxInFlight`（测试记录峰值）；同时处理的文件 ≤ `maxConcurrentFiles`。
- 暂停后不再读取、不再前进；恢复后**每个字节只读一次**（跨暂停累计读取 = 文件大小）。
- 取消保留已提交块、**不发布**（C8：取消不是删除）。
- 单个文件失败不影响同批其他文件；`retry` 清除错误。
- 进度按字节；未知分母返回 `null`，不编百分比。
- `ts_ns` 以十进制字符串保存（19 位），`ts_key` 为毫秒排序键；两列分离，避免 2^53 丢精度。

## 一处真实缺陷（已修）

`rules.applyProfile(records, profile)` 是**批量** API，最初按记录调用并传 `null` 规则，导入在第一条记录即失败（`Cannot read properties of null (reading 'id')`）。改为整块调用并传入服务器同源的 `rules/cpqpsgx-default.json`。

## 边界

- 取消后"核对原文件"只做了检查点保留，未做整文件重新校验（需 `R6-017` 的摘要路径）。
- 页面刷新后不续跑：本机计算不承诺跨关闭继续（票面允许）。
