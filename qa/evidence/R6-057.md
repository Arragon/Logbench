# R6-057 · 多根文件回收恢复与活动引用保护

**状态**：完成

## 变更

| 文件 | 变更 |
|---|---|
| `server/storage/trash.py` | 新增。每根回收目录、先写清单再移动、崩溃修复、活动引用保护、跨文件系统明确拒绝、digest 校验、旧 `trash` 表兼容 |
| `server/app.py` | v1 `DELETE /api/v1/files` / `POST /api/v1/files/restore` / `GET /api/v1/files/trash` 委托新服务（目录删除仍走旧路径，列表合并） |
| `server/storage/api.py` | `GET /api/v2/library/trash`、`POST .../trash/{id}/restore`、`DELETE /api/v2/library/files/{id}` |

## 行为要点

- 记录顺序：`pending`（含目标路径与 sha256）→ `os.replace` → `trashed`；异常置 `failed` 并保留原文。
- 引用保护：未完成任务、上传会话、查询快照、索引 pin、非空路径的共享/个人绑定；服务默认绑定不算引用。
- 绑定冲突需显式 `?detachBindings=1`，解绑与删除都写审计。
- 恢复：根离线拒绝、同名不覆盖（409）、恢复后校验 digest 并回报 `digestMismatch`。
- 私有文件仅 owner 可删/恢复/列出；管理员不因身份获得私有内容。
- 源端删除不传播：本服务只处理本地登记，不与远端同步。
