# R6-046 · 私有上传会话：身份归属、配额与保留策略

## 交付

`server/uploads/sessions.py` —— 上传不是「服务器上有个文件」，而是**某个 principal
拥有的会话**，带配额、过期时间和显式封存步骤。

### 关键设计

- **分片按摘要幂等**：重传第 7 片返回同一结果（`idempotent: true`），不会追加两次。
- **封存校验整体**：总大小 + 每片摘要都验过才拼装；缺片或短片让封存失败，
  而不是拼出一个「看起来完整」的文件。
- **`uploaded` 不等于 `indexed`**（契约 C6），`sealed` 也不等于 `indexed`：
  封存只创建文件行与索引任务，状态由任务推进。
- **配额与过期按 principal 计**：过期会话释放配额与磁盘；过期后再访问按「不存在」
  处理（`unknown_session`），而不是给一份没有分片的续传清单。
- **并发会话另有上限**：字节配额看不见「半途而废的会话」——每个会话占一个目录、
  一个文件描述符和一行记录。默认 `global 4` / `per principal 2`，
  超限返回 `429 too_many_sessions`；取消、过期或封存都会把名额还回来。
- **私有权限落盘**：会话目录 `0o700`、分片 `0o600`，与其他 principal 的数据并列存放
  但不共享可读性。
- **取消保留分片**：`DELETE` 只置状态，不清盘——给「误取消」留一次恢复机会，由 GC 回收。

## 补齐（票面验收「并发超额及时拒绝」）

初版只有字节配额，没有会话数上限——一个客户端可以开无限多个 1 KiB 的空会话，每个都占一个
目录、一个描述符和一行记录，而字节配额完全看不见这件事。现在 `UploadStore.create` 在配额
检查之后加 `_check_active()`：默认 `global 4` / `per principal 2`，超限抛
`too_many_sessions`，HTTP 映射为 **429**（`server/app.py` 的错误码表同步补上）。
取消 / 过期 / 封存都会把名额还回来，用例 `test_concurrent_sessions_are_capped_per_principal`
断言「第三个被拒、取消一个后可再建」。

## 本轮修复

`test_seal_is_idempotent` 原先只校验 `file_id` 相同，掩盖了一个真实浪费：重试封存会
再次 `register_path`（catalog 按路径+owner 去重，所以 file id 不变）并**无条件新建一个
索引任务**，等于把同一份字节再索引一遍。现在二次封存返回首次的 `job_id` 与
`index_state`，`accepted: false`，不再产生第二个任务；断言也补齐到 `job_id` 级别。
