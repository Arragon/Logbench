# R6 原型覆盖表（Rev2 新增交互）

> 票：`R6-004`　｜　原型：`docs/prototypes/r6-rev2.html`　｜　校验：`qa/r6/prototype_rev2.py`
> 证据：`qa/evidence/R6-004/`（13 张桌面状态截图 + 2 张窄屏 + `prototype-check.json`）

## 1. 三类页面，别混为一谈

| 类别 | 含义 | 本文档中的范围 |
|---|---|---|
| **A · 原模板已有** | 上一版 R6 Remote HTML 已覆盖的远程采集流程 | 仅作参照，不在本票重做 |
| **B · Rev2 新增** | 本票要补的目标形态（导入 / 搜索 / 私有上传） | 本票交付，作为后续实现验收目标 |
| **C · 复用生产页** | v3.0.3 已存在且行为已冻结的页面 | **不改**，只声明复用与差异 |

按 C 类复用的生产页：日志浏览外壳（双列导航 + 单行 toolbar + 时间线 + 虚拟表 + 详情抽屉）、文件库列表、规则管理、管理后台。原型刻意沿用其几何（208 px 导航、52 px 顶栏、44 px 工具条、28 px 行高），所以"数据区占比"可与 R5 基线直接比较。

## 2. B 类：Rev2 新增页面与状态

原型用 `?state=` 与页面内的状态选择器切换，**每个状态都是确定性样例**，没有随机进度、没有伪装的真实计数。

| 状态键 | 场景 | 关键要求 | 截图 |
|---|---|---|---|
| `open-choice` | 打开日志：本机默认 vs 服务器加速 | 本机是默认项且标注"不上传"；服务器加速标注需要身份与索引 | `desktop-open-choice.png` |
| `reading` | 逐文件读取浮层 | 读取 / 保存本机 / 分帧 / 规则检索 **四个水位分列**；任一未完成时计数只能写"至少" | `desktop-reading.png` |
| `queued` | 队列 | 未开始的显示"排队第 N 位"，不显示 0 条 | `desktop-queued.png` |
| `partial` | 部分可读 | 明确写"2 可读 / 1 失败"，失败项给重选与跳过 | `desktop-partial.png` |
| `quota` | 配额失败 | 保留已读部分，提供"仅内存读取"与"去清理" | `desktop-quota.png` |
| `search-exact` | 搜索精确结果 | 同时给出命中数与覆盖（100%，130,295/130,295） | `desktop-search-exact.png` |
| `search-partial` | 预算暂停 | 显示"至少 61 条 / 已扫描 34%"并提供"继续扫描" | `desktop-search-partial.png` |
| `search-unknown` | 计数未知 | 扫描中不显示具体条数 | `desktop-search-unknown.png` |
| `upload-offset` | 私有上传断点续传 | 显示已确认偏移、分片大小、校验方式 | `desktop-upload-offset.png` |
| `upload-uploaded` | 上传完成未索引 | 只能写"已上传 · 索引排队中"，**不能写"可检索"** | `desktop-upload-uploaded.png` |
| `library-private` | 文件库私有区域 | 私有/共享分标；索引中的条目显示"索引中" | `desktop-library-private.png` |
| `idle` | 基线对照 | 与 R5 几何一致：toolbar 1 行、数据区 75.5% | `desktop-idle.png` |

窄屏（375×812）：`narrow-375-idle.png`、`narrow-375-reading.png`。侧栏与抽屉收起，弹窗高度 487 px < 812 px。

## 3. 自动校验的硬约束

`qa/r6/prototype_rev2.py` 的 16 项检查全部 PASS，其中六项是可回归的契约：

1. **toolbar 恒为 1 行**（1366 与 375 两个视口）。Rev2 新增的"任务"入口放在工具条内，不新增整行时间按钮。
2. **数据区 ≥ 60% 视口**：1366×768 下实测 **75.5%**，与 R5 基线的 78% 同量级，没有被常驻指标区挤压。
3. **无横向溢出**（1366/375 均 `scrollWidth == innerWidth`）。
4. **`partial` 不显示"0 条"**：断言文案含"至少"且不含"0 条"。
5. **`upload-uploaded` 不出现"可检索"**：断言含"未索引"，且不出现"可检索。"这一句号结尾的肯定式。
6. **键盘可达**：`state → open → q → level → tasks → views`；`Enter` 打开对话框，`Esc` 关闭并把焦点还给状态选择器。

## 4. 出现即判缺陷的反例

原型与后续实现都按这份清单自查：

| 反例 | 为什么是缺陷 |
|---|---|
| 把 `at_least` 写成"共 243 条" | 未扫完时给出精确语气，排障会误判"只有 243 条" |
| 上传 100% 就标"可检索" | 上传完成 ≠ 索引完成（契约 C6） |
| 预算中断显示"0 条结果" | 用户会以为确实没有，实际是没扫完（`partial` ≠ zero） |
| 新增整行时间范围按钮 | 挤压主表，违反 R5 紧凑 toolbar 基线 |
| 常驻巨大指标区 | 同上；指标应放进可展开的"任务"浮层 |
| 关闭面板即停止任务 | 关闭浮层是视图操作，不是任务操作 |
| 取消上传同时删除分片/原文 | 取消 ≠ 删除（契约 C8） |
| 随机进度条/假计数 | 评审无法复现，也无法判断真实卡在哪一步 |

## 6. 未确认项（保留待评审）

- 打开方式的默认值与"服务器加速"的可见条件（是否需要登录、是否仅共享库可见）需产品确认。
- 任务角标的计数口径（运行中任务 vs 未读失败）需产品确认。
- 窄屏下"任务"入口是否并入更多菜单，需在 `R6-016` 与响应式票中确定。

这三项都不阻塞实现，因为原型已给出可切换形态；但**未经产品确认前，不得把它们当作已冻结需求**。
