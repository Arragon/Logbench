# LogBench R5 服务化实施计划

目标：保留 R5 界面、解析/搜索 Worker、虚拟列表和本机持久化；将演示服务切换为真实可部署 API。Python 3.9.11+ 标准库/SQLite；可选 WSGI 托管，不需要 npm、CDN 或独立数据库。

范围：真实 IP 身份、浏览器存储命名空间、共享规则/目录绑定/修订冲突/回收站、data 文件目录读取下载删除恢复、管理 UI、覆盖式热更新、完整 ZIP。不得默默上传本机日志，不执行 MCChecker 的 Python 文件。

决策：复用已交付 V2 的 server/app.py、HTTP/WSGI 和测试；复用 R5 的全部前端源文件与规则引擎；MCChecker 仅兼容人员数据格式和进程替换式更新模式，不拉入其业务架构。可修改文件与 data/var/config 持久数据分离。

## 工作单元
- [x] 1. 后端：先运行原测试；新增 R5 规则契约、目录元数据/无正文目录加载、删除绑定保护测试；扩展 API，验证旧服务回归。
- [x] 2. 对接：先定义端到端读取/导入/规则共享/目录绑定/身份隔离测试；保持 R5 外观，移除演示数据与假管理操作。真实权限必须由服务器检查。
- [x] 3. 热更新：变更稳定后快照、源码与导入预检、旧工作进程有序关闭、新进程启动健康检查、启动失败回退。失败版本不改变数据。不承诺零中断或数据库降级回滚。
- [x] 4. 部署：单命令入口、Windows/Linux 启动脚本、固定 origin、反代说明、更新/备份工具、版本清单。
- [x] 5. 验证：真实 HTTP、真实浏览器、重开持久缓存、两身份、恶意路径/CSRF/并发规则冲突、合法/非法热更新及数据保留；从最终 ZIP 解压重跑。

重点：缓存不能被服务元数据覆盖；个人绑定与共享绑定分层；关闭文件不删除缓存；HTTP 服务不暴露配置/数据库；API 失败不得回退成演示数据。后续授权/跨设备强认证不在本轮范围。

执行结果：详见 QA.md。第5项中的原生浏览器持久缓存重开已尝试，但受 ERR_BLOCKED_BY_ADMINISTRATOR 阻止，不属于通过项；已有目标环境测试脚本。前端联调使用真实Chromium加真实HTTP测试适配器，未改动管理员策略。
